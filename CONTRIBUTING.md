# Contributing to git-ferret

Thanks for taking the time to improve the tool. This guide covers the local workflow and what a
pull request needs. The [development guide](docs/development.md) has the longer version, and
[AGENTS.md](AGENTS.md) is the same contract for AI agents.

## Development setup

You need Python 3.14 or newer, git 2.38 or newer, and [uv](https://docs.astral.sh/uv/) (recommended)
or pip.

```console
$ git clone https://github.com/fran2889/git-ferret
$ cd git-ferret
$ uv sync --all-extras --locked
$ make hooks
$ make check
```

`make install` is the pip equivalent of `uv sync --all-extras --locked`. `make hooks` points this
repository's `core.hooksPath` at the checked-in `.githooks/` directory; the hooks chain to any
global hooks you already have, so nothing is hidden. `make check` must pass before you open a pull
request.

If you would rather not activate the environment, run `uv run --no-sync make check` after the sync
above. `--no-sync` uses the environment that is already there instead of resolving it again.

## Branches, commits, and pull requests

- Branch names are `type/kebab-case-slug`, where `type` is the Conventional Commits type used in
  the pull request title, for example `fix/shallow-clone-warning` or `docs/releasing-runbook`.
- Commit subjects use Conventional Commits: `type(scope)?: description`. The allowed types are
  `build`, `chore`, `ci`, `docs`, `feat`, `fix`, `perf`, `refactor`, `revert`, `style`, and `test`.
  The description starts lowercase, is imperative, and has no trailing period. Merge, revert,
  fixup, and squash commits pass through unchanged.
- Do not add `Generated by` or `Co-Authored-By` footers to commit messages.
- A pull request title is squash-merged and parsed by release-please, so it must also be a
  Conventional Commit.
- Add tests for behaviour changes. A bug fix needs a test that failed before the fix; a feature needs
  tests for the new path. The suite builds real git repositories and never mocks git.
- Run `make check` before pushing. `make ci` adds coverage, the build, and the dependency audit, but
  reaches the network and is slower.
- Fill in the pull request template. `gh pr create` does not apply the template automatically; pass
  a filled copy with `--body-file`. Keep the Summary to one to three bullets, one behaviour change
  each, and name the automated check plus any manual command in the Test Plan.
- The issue templates apply the `bug` and `enhancement` labels. Add any other label deliberately.
  Do not hand-apply Dependabot's automation labels.

## Documentation

Update `README.md` when user-facing behaviour changes. The README is the user manual; put the
development workflow in `docs/development.md` and troubleshooting in `docs/troubleshooting.md`. The
design notes under `docs/superpowers/` are historical records, not a second manual.

Every Python file under `git_ferret/`, `tests/`, and `scripts/` starts with the SPDX header:

```python
# SPDX-FileCopyrightText: 2026 Fran
# SPDX-License-Identifier: GPL-3.0-only
```

`make check` enforces it.
